1. Resumen

Un sistema gestor de bases de datos (SGBD, o DBMS por sus siglas en inglés) es el software que permite crear, consultar, modificar y proteger los datos de una organización, y que actúa como intermediario entre la base de datos, las aplicaciones y los usuarios. Este informe define el concepto, describe su origen y sus funciones, compara los modelos relacional, no relacional, jerárquico, en red y orientado a objetos, presenta los gestores más utilizados, y analiza su uso en procesos de talento humano bajo la Ley 1581 de 2012. Se concluye que elegir un gestor es una decisión que depende del tipo de dato, el volumen, la seguridad requerida y los recursos de la organización.

Palabras clave: base de datos, SGBD, modelo relacional, SQL, NoSQL, protección de datos personales.

2. Introducción y objetivos

Toda área de talento humano maneja datos: hojas de vida, contratos, asistencia, nómina, evaluaciones. Cuando esos datos viven en archivos sueltos aparecen duplicados, errores y riesgos de seguridad. Los gestores de bases de datos resuelven ese problema al centralizar la información con reglas de integridad y control de acceso.

Pregunta de investigación: ¿qué es un gestor de bases de datos, qué tipos existen y cómo elegir y usar uno de forma segura en un proceso de talento humano?

Objetivo general

Explicar qué son los gestores de bases de datos y cómo se aplican en la gestión del talento humano.

Objetivos específicos

  • Definir base de datos y SGBD, y describir sus funciones.
  • Comparar los principales modelos y gestores.
  • Identificar requisitos de seguridad y legales para datos de personas.
  • Proponer criterios de selección para una organización.

4. Marco teórico

4.1 Conceptos base

Una base de datos es un conjunto organizado de datos relacionados entre sí. El SGBD es el programa que la administra. La combinación de base de datos, SGBD y aplicaciones se llama sistema de base de datos (Elmasri y Navathe, 2016).

4.2 Antecedentes

AñoHito
1960sPrimeros gestores jerárquicos (IBM IMS) y en red (modelo CODASYL).
1970E. F. Codd publica el modelo relacional, que organiza los datos en tablas.
1970s–80sNace SQL en IBM; llegan Oracle, DB2 y otros. SQL se normaliza como ISO/IEC 9075.
2000sCrecen los gestores NoSQL (MongoDB, Cassandra) por las necesidades de la web y el big data.
2010s–hoyBases de datos en la nube, como servicio y con apoyo de aprendizaje automático.

4.3 Funciones de un SGBD

  • Definición: crear estructuras (tablas, campos, tipos, relaciones).
  • Manipulación: insertar, consultar, actualizar y eliminar datos, normalmente con SQL.
  • Control: usuarios, roles y permisos.
  • Integridad: reglas como llave primaria, llave foránea y campos obligatorios.
  • Concurrencia y recuperación: varios usuarios a la vez y restauración ante fallas mediante copias de respaldo.

4.4 Características

CaracterísticaSignificado
Control de redundanciaReducir datos repetidos; se logra con la normalización.
Consistencia e integridadLos datos cumplen reglas definidas y no se contradicen.
SeguridadAutenticación, permisos, cifrado y auditoría.
Independencia de datosCambiar el almacenamiento sin reescribir las aplicaciones.
FlexibilidadConsultar y combinar datos de formas no previstas al diseñar.
Propiedades ACID. Los gestores transaccionales garantizan Atomicidad (todo o nada), Consistencia, aIslamiento y Durabilidad (Haerder y Reuter, 1983). Muchos sistemas NoSQL distribuidos relajan algunas de ellas a cambio de escalabilidad, un compromiso descrito por el teorema CAP (Gilbert y Lynch, 2002).

4.5 Elementos del modelo relacional

Tabla (entidad), fila (registro), columna (campo), llave primaria (identifica cada fila de forma única), llave foránea (enlaza con otra tabla) y relaciones uno a uno, uno a muchos y muchos a muchos.

8. Seguridad y marco legal en Colombia

La Ley 1581 de 2012 regula el tratamiento de datos personales; su reglamentación se compiló en el Decreto 1074 de 2015 (antes Decreto 1377 de 2013). La autoridad de control es la Superintendencia de Industria y Comercio (SIC).

  • Datos sensibles (salud, origen étnico, orientación sexual, datos biométricos, afiliación sindical): su tratamiento está restringido y exige autorización expresa y finalidad clara.
  • Principios: finalidad, libertad, veracidad, transparencia, acceso restringido, seguridad y confidencialidad.
  • Deberes del responsable: pedir autorización, informar la finalidad y atender consultas y reclamos de los titulares. Ciertas organizaciones deben inscribir sus bases en el Registro Nacional de Bases de Datos (RNBD).
Buenas prácticas técnicas: contraseñas fuertes y roles por perfil, copias de respaldo periódicas, cifrado de datos sensibles, registro de accesos y mínimo privilegio (cada persona ve solo lo que necesita). La calidad del dato también se evalúa con la norma ISO/IEC 25012.

9. Tendencias: nube e inteligencia artificial

  • Nube y bases como servicio: la organización delega respaldo, actualización y escalado al proveedor.
  • Persistencia políglota: combinar varios tipos de gestores según el problema.
  • IA en los gestores: asistentes que generan consultas SQL desde lenguaje natural, ajuste automático del rendimiento y búsqueda vectorial (por ejemplo, la extensión pgvector de PostgreSQL). Estas respuestas deben validarse siempre: la IA puede producir consultas incorrectas, y enviar datos personales a servicios externos de IA exige autorización y control.

11. Conclusiones

  • El SGBD centraliza los datos y garantiza integridad, seguridad y acceso concurrente, lo que no ofrecen los archivos dispersos.
  • El modelo relacional con SQL sigue siendo la base de la información de talento humano, mientras que NoSQL aporta flexibilidad y escala para casos específicos.
  • Access sirve para equipos pequeños; PostgreSQL, SQL Server, MySQL u Oracle para sistemas con muchos usuarios.
  • Los datos de empleados exigen cumplir la Ley 1581 de 2012; los datos de salud son sensibles.
  • Un indicador agregado puede ocultar problemas por área: la base de datos permite desagregar y decidir con evidencia.
