Inicio

¿Por qué importan los Gestores de Bases de Datos?

El Sistema Inter-Galáctico Humano (SIGH) y la Confederación Planetaria Extraterrestre (CPE) confían en que la información de Neógenos y humanos quede bien administrada. Un Sistema Gestor de Bases de Datos (SGBD o DBMS) es el conjunto de programas que actúa como interfaz entre los datos, las aplicaciones y las personas: permite crear, almacenar, consultar, modificar, proteger y recuperar la información de forma estructurada y segura.

Esta aplicación organiza el reto en pasos: entender qué es un SGBD y sus componentes, reconocer los distintos modelos y ejemplos reales, evaluar una fuente o un dato con un criterio técnico, practicar la clasificación de gestores, y revisar tu progreso en un dashboard con gráficos y análisis, tal como lo pidió la Capitana Dorian Gaiart para la Misión Principal No 3.

Modelos de bases de datos y sus gestores

Byteon clasifica los SGBD según su modelo y flexibilidad, para elegir la herramienta óptima según cada necesidad organizacional.

M-01

Relacionales (SQL)

Organizan los datos en tablas relacionadas mediante claves primarias y foráneas. Garantizan alta integridad y transacciones ACID; el lenguaje predominante para manipularlas es SQL (Structured Query Language).

Oracle Database
MySQL
PostgreSQL
Microsoft SQL Server
MariaDB
M-02

No relacionales (NoSQL)

No requieren estructuras de datos fijas como tablas: usan documentos (JSON/BSON), pares clave-valor, columnas o grafos. Son útiles para manejar grandes volúmenes de información y estructuras que cambian con frecuencia.

MongoDB (documental)
Cassandra (columnar)
Redis (clave-valor)
Neo4j (grafo)
M-03

En la nube y en tiempo real

Plataformas gestionadas que ofrecen sincronización instantánea y alta disponibilidad para aplicaciones web y móviles. La nube no garantiza seguridad automática: necesitan reglas, autenticación y validación correctas.

Firebase
AWS Aurora
Google Cloud SQL
Profundizar: otros modelos según su estructura lógica

Jerárquico

Organiza los datos en árbol: cada registro (nodo) tiene un único padre. Ejemplos: IMS de IBM, SYSTEM 2000 de Intel.

En red

Similar al jerárquico, pero un nodo puede tener varios padres (estructura tipo plex). Propuesto por el comité CODASYL; hoy es poco frecuente por su complejidad de modificación.

Orientado a objetos

Almacena el objeto completo, con sus propias características, similar a la programación orientada a objetos. Admite mayor cantidad de contenido por registro.

¿Qué modelo conviene según el escenario?

Escenario Alternativa Justificación
Nómina y contratos PostgreSQL, SQL Server u Oracle Integridad, transacciones y auditoría.
Portal web con presupuesto limitado MySQL o PostgreSQL Costos flexibles y ecosistema web.
Expedientes con atributos variables MongoDB Modelo documental flexible; requiere gobierno de datos.
Aplicación móvil Firebase Servicio administrado y reglas de seguridad integradas.
Analítica histórica Almacén de datos / columnar Optimiza consultas analíticas sobre grandes volúmenes.

SGBD en la práctica: arquitectura y modelo relacional

Un SGBD no es solo un programa para guardar registros: permite capturar, validar, consultar, proteger, actualizar y transformar datos en información útil para decidir. En Talento Humano se aplica a hojas de vida, contratos, novedades, formación, evaluaciones, ausentismo, vacaciones, nómina, bienestar e indicadores.

Ciclo de vida de un dato dentro de un SGBD

Captura→ Validación→ Almacenamiento→ Consulta / transacción→ Respaldo→ Auditoría
Arquitectura en tres niveles (ANSI-SPARC)

Nivel externo

Es la visión de cada usuario o programador: un subesquema describe solo el subconjunto de datos que a esa persona le interesa (por ejemplo, ventas por departamento).

Nivel conceptual

Representación global e independiente del almacenamiento físico: entidades, atributos y relaciones del negocio. Solo el administrador trabaja directamente aquí.

Nivel interno

El más cercano al almacenamiento físico: estructura de archivos, índices, punteros y modos de acceso en disco.

Elementos de un sistema gestor de bases de datos

Los datos

Simples (nombre, dirección, teléfono) o compuestos (tablas). Es la materia prima que administra el SGBD.

Diccionario de datos

Contiene los metadatos: descripción, longitud, permisos de acceso y representación física de cada campo. Es la "meta-base" que describe a la base de datos.

El propio SGBD

Conjunto de programas que crean, actualizan, consultan y protegen la base de datos, mediante lenguajes de definición (DDL) y de manipulación (DML).

Administrador de la base de datos (DBA)

Responsable de la creación, gestión, seguridad y mantenimiento de la base de datos.

Los usuarios

Informáticos (con herramientas para su trabajo) y no informáticos o finales, a quienes va dirigida la base de datos.

Herramientas ofimáticas relacionales

Access 2016 permite crear tablas, consultas, formularios, informes y relaciones sin escribir SQL, ideal para introducir el modelo relacional en Talento Humano.

Principios ACID de una transacción confiable

Para que una liquidación salarial o una asignación de cargo nunca corrompa la información, el SGBD debe garantizar cuatro propiedades inquebrantables:

Propiedad ACID Significado Impacto operacional
Atomicidad Principio de "todo o nada". Si un paso de la transacción falla, se revierte todo al estado anterior.
Consistencia Solo se permiten transacciones válidas. El sistema pasa de un estado válido a otro igual de válido, respetando las reglas de negocio.
Aislamiento Operaciones simultáneas no interfieren. Evita lecturas sucias o inconsistencias cuando varios usuarios trabajan a la vez.
Durabilidad Los cambios confirmados persisten. Resisten fallos o cortes de energía una vez la transacción quedó confirmada.
Seguridad, respaldo y protección de datos personales

Respaldo y continuidad

El plan de respaldo define el RPO (pérdida máxima aceptable de datos) y el RTO (tiempo máximo de recuperación). Ejemplo: reportes con RPO de 24 horas y RTO de 4 horas; nómina crítica con RPO de 15 minutos y RTO de 1 hora.

Una copia de seguridad que nunca se ha restaurado con éxito no es una estrategia comprobada.

Seguridad, privacidad y ética

  • Aplicar mínimo privilegio y roles por función (RBAC).
  • Separar registro, aprobación y cierre de novedades.
  • Usar autenticación robusta, trazabilidad y revisión de permisos.
  • Evitar concatenar entradas de usuario en SQL: usar consultas parametrizadas.
  • En Colombia, la Ley 1581 de 2012 regula el tratamiento de datos personales de talento humano.

Actividad presencial: auditoría exprés de una base de datos de Talento Humano

A diferencia del juego digital de clasificación, esta dinámica pone a cada equipo en el papel de auditor(a): reciben un caso real de una base de datos ficticia con un problema, y deben diagnosticarlo y proponer una solución, tal como pidió la Capitana Dorian Gaiart.

Cómo organizarla

  1. Forma equipos de 3 a 4 personas. Cada equipo será el "equipo auditor" de un caso.
  2. Imprime y recorta las 8 fichas de caso con el botón de abajo (cada ficha describe un problema detectado en una base de datos de Talento Humano, sin revelar la causa).
  3. Reparte una ficha distinta a cada equipo (si hay más equipos que fichas, puedes repetir alguna).
  4. Da 10 minutos para que cada equipo: (a) diagnostique qué principio o dimensión de calidad se está violando (ACID, seguridad, unicidad, consistencia, trazabilidad o respaldo); (b) proponga una acción concreta para solucionarlo; y (c) estime si el riesgo para la organización es alto, medio o bajo.
  5. Cada equipo expone su diagnóstico en un minuto ante los demás.
  6. Revisa los resultados con la hoja de respuestas del docente (segunda página de la impresión) y discutan los casos donde hubo desacuerdo.
  7. Cierre grupal: cada equipo comparte un caso parecido que haya visto en su propia experiencia laboral o de prácticas, y a qué principio de los estudiados corresponde.
